# Internationalization (i18n)

This document explains the internationalization (i18n) setup for the application, supporting multiple languages.

## Overview

The application features a custom i18n solution without relying on external libraries like `react-i18next`. It currently supports multiple languages, predominantly English (`en`) and Spanish (`es`).

## Data Structure

Translation keys and strings are stored centrally in `src/data/translations.ts`. The file exports language dictionaries containing key-value pairs for all text used throughout the interface.

```typescript
// Example from src/data/translations.ts
export type Language = "es" | "en" | "de" | "it";

export const translations = {
  en: {
    nav_home: "Home",
    // ...
  },
  es: {
    nav_home: "Inicio",
    // ...
  }
};
```

## State Management and Persistence

The selected language is managed via React state at the root level (`App.tsx`) and passed down to child components as a prop.

Language preferences are persisted across browser sessions using `localStorage` under the key `app_lang`. If no selection has been made, the application defaults to English (`en`).

```tsx
// Inside App.tsx
const [lang, setLang] = useState<Language>(() => {
  const savedLang = localStorage.getItem("app_lang");
  return (savedLang as Language) || "en";
});

const handleSetLang = (newLang: Language) => {
  setLang(newLang);
  localStorage.setItem("app_lang", newLang);
};
```

## Component Integration

To utilize translated strings, page and shared components **MUST** accept a `t` prop, which represents the active translation dictionary object.

```tsx
// Example Component Integration
interface ComponentProps {
  t: Record<string, string>;
}

const Footer = ({ t }: ComponentProps) => {
  return (
    <footer>
      <p>{t.footer_copy1}</p>
    </footer>
  );
};
```

When building new components or routes, ensure they are integrated with this `t` prop to maintain consistent localization.
